**Command:** `npm run evals -- --tasks hacker_news,edgar,openclaw_pr --k 3`
**Headline: 0 of 3 tasks passed.** The agent is close on one task and blocked by two specific, diagnosable problems on the others.

---

## What was measured

The eval harness ran each of the three "easy" tasks **3 times each (k=3)** — nine live agent runs total, each in a fresh browser tab against the live web. After each run, the grader fetched fresh ground truth from the task's authoritative API (its *oracle*) and checked the run directory's artifacts against it. Graders can only see the run directory and the oracle data — never the agent's conversation — so an agent that merely *describes* success cannot pass.

Three metrics, as defined in the design:

- **Accuracy** — mean fraction of grading assertions passed across the 3 trials.
- **Completion** — how many of the 3 trials passed *all* assertions.
- **Task pass** — all 3 trials complete. This is deliberately strict: it measures consistency, not just capability.

## Failure mode 1 — Volunteering extra structure (Hacker News, 1 of 3 trials)

The task asks for a CSV "with columns for title, URL, and points." Trial 2 produced `rank,title,url,points` — correct data, plus a helpful-seeming `rank` column nobody asked for. The grader (per the ruling that the task's named columns are exact) failed exactly that one assertion; all data-quality assertions passed.

This is a *tendency*, not a fluke: both pre-baseline demo runs of the same task also added `rank`. Two of three baseline trials happened to resist it.

**Candidate general mechanism:** a system-prompt line on schema exactness — when a task specifies output structure, produce exactly that structure. Cheap, general, testable by re-running.

## Failure mode 2 — Downloads blocked by SEC's edge (EDGAR, 3 of 3 trials)

The agent found the correct filing every time. The chain that then broke:

1. On the filing page, document links point at SEC's iXBRL **viewer wrapper** (`sec.gov/ix?doc=/Archives/...`), not the raw file.
2. The `download` tool fetches through Playwright's request client (shares cookies, but **not** Chrome's real network stack). SEC's edge returned **HTTP 403** to it — while the same URLs load fine when the agent *navigates* the actual page.
3. The agent correctly diagnosed this and started re-routing to raw `/Archives/` URLs — and then the run hit its turn budget (see failure mode 3). No trial ever landed the document, so the hash-match assertion failed 3/3. Screenshot and provenance assertions passed 3/3.

**A pattern worth noting:** SEC blocked *three different* non-browser clients tonight — `curl`, Node's `fetch` (until the User-Agent was changed to SEC's plain `Name email` format, which fixed the oracle), and Playwright's request client. Only real Chrome was consistently accepted. Any download mechanism that doesn't go through the page's own network stack will keep meeting this on hardened sites.

**Candidate general mechanism:** teach `download` to fall back to an in-page fetch (the page's own network stack and session) and/or Playwright download-event capture — both were already noted in the tool's docstring as the alternative for wrapper/JS-triggered downloads.

## Failure mode 3 — The 12-turn budget is too tight for deep tasks (EDGAR 3/3, OpenClaw 1/3)

All three EDGAR trials ended `budget_exceeded` at 11–12 turns while *actively and correctly recovering* from failure mode 2. EDGAR's natural depth (search → results → filing index → document, plus verification screenshots) leaves no headroom for even one recovery loop. One OpenClaw trial also died at 12 turns mid-investigation.

The agents ran out of turns, not ideas — transcripts show sound diagnosis right up to the cutoff.

**Candidate general mechanism:** raise the default `maxTurns` (a config value in the composition root, currently 12 — e.g. 24). The cumulative token ceiling (250k) remains the real cost guard. Note the cost interaction: only the prompt prefix is cached, so late turns on deep tasks cost ~20–35k fresh input tokens each; more turns means visibly more spend per run.

## Failure mode 4 — Ambiguity pulls the agent off its anchor (OpenClaw, 2 of 3 trials)

GitHub hosts two plausible "OpenClaw" repositories: `openclaw/openclaw` (intended by the oracle; the start page every trial opened on) and `pjasicek/OpenClaw` (a Captain Claw game engine). What happened:

- **Trial 1** noticed the collision, decided to "check both," and burned its remaining turns — ending with **no `answer.md` at all** (2 assertions failed).
- **Trial 2** stayed on the start-page repo and passed everything.
- **Trial 3** concluded the game engine was the intended repo and wrote a thorough, well-evidenced answer — about the wrong repository's PR #203.

This is the purest *consistency* failure in the baseline: same task, three different behaviors.

**Candidate general mechanism:** a system-prompt line on anchoring — treat the run's starting page as task context and prefer interpretations consistent with it, rather than free-roaming disambiguation. (More turn headroom from mechanism 3 would likely also have saved trial 1.)

## What held up

- **Provenance (the product):** manifest hashes re-verified against artifact bytes in 9/9 runs. Screenshots carried their source URLs.
- **Prompt caching:** stable cache reads on every turn ≥ 2 of all nine runs.
- **Grading integrity:** the strict graders caught exactly what they were designed to catch, including the extra-column case ruled on earlier today; no false failures observed.
- **Error recovery reasoning:** agents read tool errors and re-routed sensibly; the losses were tooling reach (F2) and budget (F3), not judgment.
- **Fail-fast harness:** two pre-baseline defects (placeholder `about:blank` start URLs; SEC rejecting a decorated oracle User-Agent) each crashed the run in seconds with precise errors, and were fixed and committed before this baseline.

## Open decisions (in your hands)

1. **Which of mechanisms 1–4 to apply, and in what order.** They are independent; each is small. F2+F3 together unblock EDGAR; F1 alone likely flips Hacker News to a task pass; F4 addresses the consistency gap.
2. **Re-baseline after applying** — same command, fresh k=3 — to attribute improvement per mechanism (apply all four at once for speed, or in stages for cleaner attribution).
3. **The disabled-thinking flag.** Its named revival trigger (disappointing baseline accuracy) is now met. Enabling adaptive thinking requires extending the loop's message types to carry thinking blocks (a contained change to the T7 types, T9 stream assembler, and replay path). The case for waiting: mechanisms 1–4 are cheaper and their effects would be confounded if everything changes at once. The case for now: accuracy is priority #1 and two tasks failed on behavior, not just tooling.
