                    - heading "What Problem This Solves" [level=2] [ref=f11e255]
                    - paragraph [ref=f11e256]:
                      - text: Resolves a problem where multi-agent installations persisted an ambient
                      - code [ref=f11e257]: "default: true"
                      - text: marker and then inferred that agent across sessions, channels, automation, and authorization paths. After roster changes or restart, that implicit default could select the wrong agent, lose a legacy owner, or allow colliding bare session keys such as
                      - code [ref=f11e258]: global
                      - text: to be attributed to the requester instead of their durable owner.
                    - heading "Why This Change Was Made" [level=2] [ref=f11e259]
                    - paragraph [ref=f11e260]:
                      - text: The final design removes the stored default marker and uses sole-agent-or-explicit selection. A write-once
                      - code [ref=f11e261]: "agents.ownership: \"explicit\""
                      - text: stamp records intentional roster ownership, while a load-time WeakMap sidecar retains the legacy owner only as migration evidence and compatibility input.
                    - paragraph [ref=f11e262]:
                      - text: "Before retiring the marker, compatibility ownership is materialized into the surfaces that need durable identity: channel bindings, heartbeat, system-agent and Talk settings, auth inheritance, and the configured fixed session store. Fixed-store rows follow the persisted owner contract ("
                      - code [ref=f11e263]: configured
                      - text: ","
                      - code [ref=f11e264]: retired
                      - text: ", or"
                      - code [ref=f11e265]: none
                      - text: ); configured ownership is authoritative, retired ownership fails closed, and authorization surfaces reject conflicting explicit agents.
                    - paragraph [ref=f11e266]:
                      - text: The same ownership ladder now covers Gateway, CLI/TUI, session aliases and IDs, task runtimes, active runs, broadcasts, transcript lookup, and migration/recovery paths. Plugin discovery uses the config-wide manifest registry. Gateway protocol additions (
                      - code [ref=f11e267]: ownership
                      - text: and
                      - code [ref=f11e268]: selectionRequired
                      - text: ) remain additive, and Doctor owns the shipped config/data migrations.
                    - heading "User Impact" [level=2] [ref=f11e269]
                    - paragraph [ref=f11e270]: Single-agent installations continue to select their sole agent without extra configuration. Multi-agent installations now receive an actionable explicit-selection response instead of silently adopting a default or another agent's session/task state. Existing installations retain and durably materialize their legacy owner during migration, including bare fixed-store sessions, while conflicting and ownerless authorization requests fail closed.
                    - paragraph [ref=f11e271]: Operators also get Doctor repairs for marker retirement, fixed-store ownership, heartbeat cadence, and startup-owned cron rows. Remote clients can consume the additive ownership metadata without breaking older protocol consumers.
