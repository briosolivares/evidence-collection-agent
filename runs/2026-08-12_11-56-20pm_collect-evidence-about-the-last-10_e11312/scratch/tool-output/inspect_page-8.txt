                    - heading "What Problem This Solves" [level=2] [ref=f9e254]
                    - paragraph [ref=f9e255]: Fixes an issue where users updating to a runtime that bundles a previously managed official plugin could repeatedly fail gateway startup convergence. The stale managed package was removed, but its persisted install record could still make the subsequent missing-plugin repair reinstall the same package and change the migration fingerprint.
                    - heading "Why This Change Was Made" [level=2] [ref=f9e256]
                    - paragraph [ref=f9e257]: Bundled-plugin retirement now captures one authoritative installed-plugin baseline, removes both the obsolete managed payload and its persisted install record, and passes that filtered baseline through the remaining convergence repairs before the final record map is persisted. This keeps unchanged startup convergence read-only, preserves retained managed overrides and external plugins, and leaves the fail-closed identity checkpoint intact for genuine external drift.
                    - heading "User Impact" [level=2] [ref=f9e258]
                    - paragraph [ref=f9e259]: Gateways can converge after an update replaces a managed official plugin with the bundled runtime copy, without repeatedly reinstalling the retired package or creating new managed generation directories.
